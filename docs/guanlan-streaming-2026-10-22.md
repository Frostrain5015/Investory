# 观澜对话流修复与工具折叠（v6.3.8）

## 行为

- 连接中断、上下文错误、请求失败、用户停止均追加独立的状态行。已收到的正文、工具步骤、策略卡与报告附件继续保留。
- 状态行使用琥珀色图标与短句，不进入普通回答气泡，也不会作为 system 指令发送给模型。
- 中断时结束未完成工具的动画，保留已完成步骤及其摘要。停止后的旧连接事件不再修改当前对话。
- 连续多个工具默认折叠为“正在运行工具”或“已运行 X 个工具”；正文、思考会分隔工具组。一级状态灯汇总子步骤，展开后可查看每条调用。
- 主轨迹与子工具轨迹保留连线；折叠动画尊重减少动态效果设置。
- 后端在 finally 中保存部分回答、仅有工具的回答、附件占位及异常状态。长轨迹 JSON 分段写入 TEXT，读取时先拼接再解析，避免原 16000 字符上限丢弃整段轨迹。

## 针对 StockSage 长时间等待

“帮我分析一下圣泉集团这只股票最近的走势”改为读取 90 天行情，不预取完整报告或市场风险引擎。明确要求深度报告时仍提供完整量化工具。

SSE 立即发送连接注释，并由独立工作线程每 15 秒发送心跳。心跳不占重放日志。量化引擎 HTTP 读超时不再触发第二次 CLI 执行；只有明确连接拒绝可走 CLI。进程另设 10 分钟看门狗，避免 stdout 阻塞绕过 waitFor 超时。

未读取线上这次故障的完整请求链，不能把具体代理超时或单个行情源认定为已证实的唯一根因。

- `node frontend/scripts/test-chat-browser.mjs`：真实 ChatPanel、模拟 API/SSE，覆盖网络中断、用户停止、上下文错误、请求错误、旧事件、历史恢复、工具折叠、一级状态、连线，以及亮色、暗色和窄屏。
- 浏览器回归使用主机 Playwright；可设置 `PLAYWRIGHT_MODULE`、`CHAT_TEST_BROWSER`、`TEST_ARTIFACT_DIR`，不增加生产依赖。
- Java 全套 109 项，103 通过，6 项需外部环境的既有测试跳过；H2 验证两个历史端点恢复中断记录及长轨迹。
- Python 全套 63 项通过；离线 smoke eval 4 场景、28 项检查通过，15 项依赖真实模型的检查跳过。
- 云端预检确认 `ai_chat_history.role` 是 `varchar(20)`、`content` 是 `text`，无需表结构迁移。

模拟流回归证明界面与记录保留行为，不代表对云端模型服务可用性或所有外部行情源进行了端到端验证。
